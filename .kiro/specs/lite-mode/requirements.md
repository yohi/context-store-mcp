# 要件定義書

## はじめに

本ドキュメントは、Context Store MCPシステムに「Liteモード」を実装するための要件を定義します。Liteモードは、インフラ要件を削減し、個人用PCで効率的に動作できるようにすると同時に、手動介入を最小限に抑える自動データ収集機能を追加します。主な目標は、重量級のマルチデータベースアーキテクチャから、個人マシンで継続的に実行できる軽量なPostgreSQLのみのソリューションへとシステムを変革することです。

## 用語集

- **Liteモード**: PostgreSQLのみを使用し、Neo4jとRedisの依存関係を排除した軽量動作モード
- **Context Store MCP**: Model Context Protocolに基づくAIエージェント向け長期記憶システム
- **Collector（コレクター）**: ログファイルを監視し、会話データを抽出して保存する自動化スクリプト
- **Graph Store（グラフストア）**: 関係性データを保存するNeo4jベースのストレージコンポーネント
- **Vector Store（ベクトルストア）**: 埋め込みベクトルを保存するpgvector拡張を持つPostgreSQL
- **Episode Memory（エピソード記憶）**: ユーザーとAIエージェント間の時系列会話記録
- **MCP Server（MCPサーバー）**: Model Context Protocolインターフェースを実装するサーバーコンポーネント
- **AI IDE**: AI機能を搭載したコードエディタ（Cursor、Windsurf、Copilot、Clineなど）
- **AIエージェント**: CLIベースのAIコーディングアシスタント（ClaudeCode、GeminiCLI、CodexCLI、CursorCLIなど）
- **AI Desktop App**: デスクトップアプリケーション型のAIアシスタント（Claude Desktop、ChatGPT Desktopなど）
- **Embedding Provider（埋め込みプロバイダー）**: テキストをベクトル埋め込みに変換するサービス（OpenAI API、ローカルCLI、カスタムAPIなど）

## 要件

### 要件1

**ユーザーストーリー:** 個人ユーザーとして、最小限のインフラ要件でContext Store MCPを実行したい。そうすることで、過度なリソース消費なしに個人用コンピューターで継続的に使用できる。

#### 受入基準

1. WHEN システムがLiteモードで起動する THEN システムはNeo4jやRedisを必要とせず、PostgreSQLのみを使用して動作しなければならない
2. WHEN Neo4jが利用できない THEN システムはグラフストレージ機能なしで通常動作を継続しなければならない
3. WHEN Redisが利用できない THEN システムはフォールバックとしてインメモリキャッシュを使用しなければならない
4. WHEN システムがLiteモード設定を検出する THEN システムはグラフストアとRedis接続の初期化をスキップしなければならない
5. WHERE Liteモードが有効な場合、THE システムはアイドル動作中に500MB未満のメモリを消費しなければならない

### 要件2

**ユーザーストーリー:** 開発者として、環境変数を通じてLiteモードを設定したい。そうすることで、フルモードとLiteモードの設定を簡単に切り替えられる。

#### 受入基準

1. WHEN 環境変数`LITE_MODE=true`が設定される THEN システムはLiteモードを有効化しなければならない
2. WHEN 環境変数`ENABLE_GRAPH_STORE=false`が設定される THEN システムはNeo4jグラフストレージ操作を無効化しなければならない
3. WHEN 環境変数`ENABLE_REDIS_CACHE=false`が設定される THEN システムはRedisの代わりにインメモリキャッシュを使用しなければならない
4. WHEN Liteモード環境変数が欠落している THEN システムはすべての依存関係を持つフルモードをデフォルトとしなければならない
5. WHEN 無効なLiteモード設定が検出される THEN システムは警告をログに記録し、安全なデフォルト値を使用しなければならない

### 要件3

**ユーザーストーリー:** 個人ユーザーとして、AI IDE、AIエージェント、AI Desktop Appから会話データを自動的に収集してほしい。そうすることで、手動で記憶を保存する必要がなくなる。

#### 受入基準

1. WHEN コレクターがAI Desktop App（Claude Desktop、ChatGPT Desktopなど）のログを監視する THEN システムはリアルタイムで新しい会話エントリを検出しなければならない
2. WHEN コレクターがAI IDE（Cursor、Windsurf、Copilot、Clineなど）のログを監視する THEN システムはリアルタイムで新しい会話エントリを検出しなければならない
3. WHEN コレクターがAIエージェント（ClaudeCode、GeminiCLI、CodexCLI、CursorCLIなど）のログを監視する THEN システムはリアルタイムで新しい会話エントリを検出しなければならない
4. WHEN 新しい会話データが検出される THEN システムはユーザーメッセージとAI応答を個別に解析しなければならない
5. WHEN 解析された会話データが有効である THEN システムは適切なメタデータとともにエピソード記憶として保存しなければならない
6. WHEN ログファイルの解析が失敗する THEN システムはエラーをログに記録し、クラッシュせずに監視を継続しなければならない

### 要件4

**ユーザーストーリー:** 個人ユーザーとして、収集された会話にソースとプロジェクト情報が自動的にタグ付けされてほしい。そうすることで、記憶を簡単にフィルタリングおよび検索できる。

#### 受入基準

1. WHEN コレクターがAI Desktop Appから記憶を保存する THEN システムはタグ`source:{app_name}`（例：`source:claude-desktop`、`source:chatgpt-desktop`）を追加しなければならない
2. WHEN コレクターがAI IDEから記憶を保存する THEN システムはタグ`source:{ide_name}`（例：`source:cursor`、`source:windsurf`）を追加しなければならない
3. WHEN コレクターがAIエージェントから記憶を保存する THEN システムはタグ`source:{agent_name}`（例：`source:claude-code`、`source:gemini-cli`）を追加しなければならない
4. WHEN コレクターがプロジェクトコンテキストを検出する THEN システムはタグ`project:{project_name}`を追加しなければならない
5. WHEN コレクターが会話データを保存する THEN システムはそれをエピソード記憶タイプとして分類しなければならない
6. WHEN 複数のタグが該当する THEN システムはすべての関連タグを記憶とともに保存しなければならない

### 要件5

**ユーザーストーリー:** 開発者として、コレクターを独立したプロセスとしてデプロイしたい。そうすることで、MCPサーバーとは別に独立して実行および管理できる。

#### 受入基準

1. WHEN コレクタープロセスが起動する THEN システムはMCPサーバーまたはPostgreSQLデータベースへの接続を確立しなければならない
2. WHEN コレクターがファイル変更を検出する THEN システムは前回のチェック以降の新しいコンテンツのみを処理しなければならない
3. WHEN コレクターが接続エラーに遭遇する THEN システムは指数バックオフで再試行しなければならない
4. WHEN コレクターが停止される THEN システムは再開のためにログファイル内の現在位置を保存しなければならない
5. WHEN 複数のコレクターが同時に実行される THEN システムは重複した記憶の保存を防止しなければならない

### 要件6

**ユーザーストーリー:** 個人ユーザーとして、簡素化されたMCPクライアント設定がほしい。そうすることで、各種AI Desktop AppやAI IDEをContext Storeに素早く接続できる。

#### 受入基準

1. WHEN システムが設定例を提供する THEN システムは主要なMCPクライアント（Claude Desktop、Cursorなど）の設定フォーマットを含めなければならない
2. WHEN システムが設定例を提供する THEN システムはDockerとローカルNode.js実行の両方の方法を含めなければならない
3. WHEN ユーザーが設定生成を要求する THEN システムは有効なMCP設定ファイルを作成しなければならない
4. WHEN 設定が生成される THEN システムはユーザーの環境に適した正しいコマンドと引数を含めなければならない
5. WHEN 設定ドキュメントが提供される THEN システムは一般的な接続問題のトラブルシューティング手順を含めなければならない

### 要件7

**ユーザーストーリー:** 個人ユーザーとして、検索結果が最近の手続き記憶を優先してほしい。そうすることで、最近遭遇した問題の解決策を素早く見つけられる。

#### 受入基準

1. WHEN Liteモードで検索クエリが実行される THEN システムは新しさスコアにより高い重みを適用しなければならない
2. WHEN 検索結果で手続き記憶タイプが検出される THEN システムはその関連性スコアを向上させなければならない
3. WHEN クエリとともにファイルパスコンテキストが提供される THEN システムは同じファイルパスに関連付けられた記憶を優先しなければならない
4. WHEN 複数の記憶が同様の関連性を持つ THEN システムはより最近の記憶を上位にランク付けしなければならない
5. WHEN 検索パラメータが指定されない THEN システムは個人使用向けにLiteモード最適化されたデフォルト値を使用しなければならない

### 要件8

**ユーザーストーリー:** 開発者として、Docker Compose設定がLiteモードをサポートしてほしい。そうすることで、必要なサービスのみを実行できる。

#### 受入基準

1. WHEN Liteモードが設定される THEN docker-compose.ymlはPostgreSQLサービスのみを起動しなければならない
2. WHEN フルモードが設定される THEN docker-compose.ymlはPostgreSQL、Neo4j、Redisサービスを起動しなければならない
3. WHEN システムがDockerプロファイルを使用する THEN システムはLiteモードとフルモード用の個別プロファイルを提供しなければならない
4. WHEN PostgreSQLサービスが起動する THEN システムは外部接続用にポート5432を公開しなければならない
5. WHEN サービスが停止される THEN システムは将来の再起動のためにデータボリュームを保持しなければならない

### 要件9

**ユーザーストーリー:** 個人ユーザーとして、シンプルなインターフェースを通じて保存された記憶を閲覧したい。そうすることで、会話履歴を参照および検索できる。

#### 受入基準

1. WHEN シンプルなUIが要求される THEN システムはPostgreSQLデータ用のWebベースビューアを提供しなければならない
2. WHEN ビューアが記憶を表示する THEN システムはタイムスタンプ付きで時系列順に表示しなければならない
3. WHEN ビューアが検索を提供する THEN システムはテキストベースとベクトル類似性検索の両方をサポートしなければならない
4. WHEN 検索結果が表示される THEN システムは一致するコンテンツをハイライトし、関連性スコアを表示しなければならない
5. WHEN ビューアがアクセスされる THEN システムはユーザーデータを保護するために認証を要求しなければならない

### 要件10

**ユーザーストーリー:** 開発者として、複数の埋め込み生成方法をサポートしてほしい。そうすることで、OpenAI APIに依存せず、ローカルCLIツール（GeminiCLI、ClaudeCode、CodexCLI、CursorCLIなど）やその他のAPIプロバイダーを使用できる。

#### 受入基準

1. WHEN 環境変数`EMBEDDING_PROVIDER`が設定される THEN システムは指定されたプロバイダー（openai、local-cli、custom-api）を使用しなければならない
2. WHEN `EMBEDDING_PROVIDER=local-cli`が設定される THEN システムは環境変数`EMBEDDING_CLI_COMMAND`で指定されたCLIコマンド（例：`gemini-cli embed`、`claude-code embed`、`cursor-cli embed`）を実行してベクトル埋め込みを生成しなければならない
3. WHEN `EMBEDDING_PROVIDER=custom-api`が設定される THEN システムは環境変数`EMBEDDING_API_ENDPOINT`で指定されたカスタムAPIエンドポイントにリクエストを送信しなければならない
4. WHEN 埋め込みプロバイダーが設定されていない THEN システムはOpenAI APIをデフォルトとして使用しなければならない
5. WHEN 埋め込み生成が失敗する THEN システムはエラーをログに記録し、ベクトル検索なしで記憶を保存しなければならない

### 要件11

**ユーザーストーリー:** 開発者として、オプションの依存関係が欠落している場合に優雅な劣化を望む。そうすることで、不完全なインストールでもシステムが機能し続ける。

#### 受入基準

1. WHEN Neo4jドライバーがインストールされていない THEN システムは正常に起動し、グラフ機能の欠落について警告をログに記録しなければならない
2. WHEN Redisクライアントがインストールされていない THEN システムは正常に起動し、インメモリキャッシュを使用しなければならない
3. WHEN 埋め込み生成サービス（APIまたはCLI）が利用できない THEN システムはストレージ操作を許可するが、ベクトル埋め込み生成を無効化しなければならない
4. WHEN オプションの依存関係の読み込みが失敗する THEN システムはどの機能が利用できないかをログに記録しなければならない
5. WHEN すべての必須依存関係が存在する THEN システムはオプションの依存関係に関係なく完全な機能で動作しなければならない
